## מה חייב להישמר במימוש

המימוש בפרודקשן חייב לשמר את המאושר:

- **היררכיה** — סדר האזורים והמשקל היחסי ביניהם
- **סדר המידע** — מה נקרא ראשון ומה אחריו
- **צפיפות** — כמה מוצג כברירת מחדל
- **פעולות** — אילו פעולות קיימות ואיפה הן יושבות
- **חשיפה הדרגתית** — מה מוסתר עד שמבקשים אותו במפורש
- **מודל האינטראקציה** — איך נפתח, איך נסגר, מה קורה תוך כדי
- **הנוסח** — הטקסטים בעברית כפי שהם
- **מצבים** — טיוטה, נעול, ממתין, הושלם, חריגה
- **התנהגות בשולחני ובמובייל** — כולל 375 פיקסל

**כל סטייה ברמת המוצר דורשת הכרעה מוצרית מפורשת.** לא "בערך ככה".

## הכרעות ארכיטקטורה ובעלות על נתונים

### "ממתין לאחרים" — תצוגה נגזרת

המקטע מורכב מהישויות הקיימות עצמן: בקשות לקוח, שאלון נתוני מס, הצעת מחיר שממתינה
לאישור, ופעולות אחרות שבבעלות הלקוח או גורם חיצוני.

- **אינו** רשימת משימות מקבילה ששומרים בנפרד
- **אין** לו סדר ידני בשלב הזה
- אינו מתחרה בתור העבודה הידני של הרו״ח

### פריטי תהליך במסך המשימות — נגזרים ממצב המסע

משימה כמו «קליטת יעל כהן» נגזרת ממצב מסע הלקוח ומציגה את הצעד המשמעותי הנוכחי.

- **אינה** שורת משימה רגילה משוכפלת שצריך לסנכרן
- מקור האמת היחיד הוא מסע הלקוח

### בקשת לקוח שנולדת מחריגה ביישור קו

נוצרת תמיד כ**טיוטה** ועוברת את מודל הפרסום המאושר — גם ללקוח ותיק וגם ללקוח פעיל.
**אינה נשלחת אוטומטית.**
