# עובד אוטומציה מקומי — PIVO

תהליך Node שרץ על מחשב המשרד (לא בדפדפן, לא ב-Vercel, לא ב-Supabase Edge) ומבצע
משימות אוטומציה שנוצרו ב-PIVO. לארכיטקטורה המלאה:
`docs/PIVO-AUTOMATION-FOUNDATION.html`.

**דרישות:** Node 18+ ו-Google Chrome. `npm install` פעם אחת (playwright-core).

## מה הרו"ח רואה

בכותרת PIVO יש שתי נוריות: **שע״ם** ו**ביטוח לאומי**.

| מצב | מראה | מה לעשות |
|---|---|---|
| מחשב האוטומציה כבוי | אפור מעומעם, לא לחיץ | להפעיל את העובד (ראה למטה) |
| לא מחובר | אפור, לחיץ | ללחוץ — חלון שע״ם ייפתח |
| ממתין לאימות | כתום | להשלים אישור דיגיטלי + PIN **בחלון שנפתח** |
| מחובר | ירוק | כלום. לחיצה מתנתקת |

‼ הרו"ח **אינו** אמור לפתוח קובץ `.bat` או טרמינל בשגרה. לחיצה על "שע״ם"
היא שגורמת לעובד לפתוח את החלון. `launch-shaam-chrome.bat` נשאר ככלי שחזור
בלבד.

‼ האוטומציה לעולם אינה נוגעת בבחירת אישור, ב-PIN או ב-OTP. היא פותחת חלון
גלוי ועוצרת.

## מחשב עבודה נוסף (203)

PIVO אינה קשורה למחשב אחד. כל מחשב שרשום לחשבון, חי, ובעל היכולת (שע״ם/ב״ל)
יכול להריץ אוטומציה — ומשימה מבוצעת לכל היותר פעם אחת, גם כשכמה מחשבים דלוקים.

1. ב-PIVO: תפריט החשבון ← **«חיבור מחשב עבודה»** ⇒ קוד חד-פעמי (15 דקות).
2. במחשב החדש: עותק של `worker/` תחת `C:\Users\<משתמש>\PIVO\worker-production\worker`
   (לא תחת `AppData` — ראה למטה), ואז:
   ```
   powershell -NoProfile -ExecutionPolicy Bypass -File worker\install-workstation.ps1 -Code <הקוד>
   ```
   מתקין תלויות, רושם את המחשב (זהות + אסימון אישי ב-`worker\.env`, רק שם),
   ומתקין הפעלה אוטומטית + watchdog.
3. בפעם הראשונה שעובדים מהמחשב הזה: «שע״ם» / «ביטוח לאומי» בכותרת ⇒
   התחברות רגילה בחלון שנפתח **במחשב הזה**. פרופילי Chrome, כרטיס חכם וסיסמאות
   נשארים מקומיים; שום דבר לא מועתק ממחשב למחשב.

**זהות ואבטחה:** כל מחשב מזדהה באסימון משלו; המסד שומר רק sha256 שלו, והשרת
גוזר ממנו את החשבון (העובד לא «אומר» בשביל מי הוא עובד). תהליך שני עם אותה
זהות — כפול באותו מחשב או `.env` שהועתק — לא תופס עבודה בזמן שהראשון חי.
ביטול מחשב: `update automation_workers set revoked_at = now() where worker_id = …`.
הסוד המשותף הישן (`PIVO_WORKER_SECRET`) עובד רק לזהות שעוד לא נרשמה, וכבוי
בפרודקשן (`AUTOMATION_LEGACY_SECRET=off`).

**איזה מחשב לוקח מה:** רק מחשב עם היכולת; משימה שצריכה חיבור לרשות — קודם
מחשב שהחיבור פתוח בו; התחברות (אדם ליד המחשב) — המחשב שבו נגעו לאחרונה
במקלדת/עכבר. בין כולם התפיסה אטומית (`FOR UPDATE SKIP LOCKED`).

**פעולה משנה מול רשות** (`shaam.create_representation`, `shaam.submit_poa`,
`btl.create_representation`): ניסיון אחד. `progress.externalAttempt` נרשם לפני
הלחיצה; מחשב שנפל אחרי זה משאיר את המשימה ב-needs_human — אף מחשב אחר לא
ממשיך אותה לבד. המשך רק באישור מפורש מהמסך, אחרי בדיקה קוראת-בלבד.

## הקמה חד-פעמית

1. להשיג את סוד העובד (רק פעם אחת, לא נחשף בשום מקום אחר):
   ```bash
   node scripts/print-worker-secret.mjs prod
   ```
2. להשיג את ה-`user_id` (uuid) שלך — מ-Supabase Studio → Authentication → Users,
   או משורת `clients` קיימת בטבלה.
3. להעתיק את הקובץ ולמלא:
   ```bash
   cp worker/.env.example worker/.env
   ```
   ולערוך את `worker/.env`: `PIVO_WORKER_SECRET`, `PIVO_USER_ID`.
   `worker/.env` לא נכנס ל-Git (מכוסה ב-`.gitignore` הראשי של הריפו).

4. להתקין את ההפעלה האוטומטית (פעם אחת):
   ```
   worker\install-autostart.bat
   ```
   יוצר קיצור דרך בתיקיית ה-Startup של המשתמש, כך שהעובד עולה בכל כניסה
   למחשב, בלי חלון שחור ובלי צעד ידני. הוא גם מפעיל אותו מיד.

   **למה Startup ולא שירות Windows:** אין צורך בהרשאות מנהל, והעובד *חייב*
   לרוץ בתוך הסשן של המשתמש — הוא פותח חלון Chrome גלוי שהרו"ח מתחבר בו.
   שירות שרץ ב-session 0 לא יכול להציג חלון בכלל.

   לביטול: `Win+R` → `shell:startup` → למחוק את הקיצור.

   **‼ מיקום העותק הקבוע: `C:\Users\guyas\PIVO\worker-production` — לעולם לא
   תחת `AppData`.** אפליקציית Claude לדסקטופ היא חבילת MSIX, ו-Windows מפנה
   כל כתיבה שלה (ושל כל תהליך שהיא מריצה) לתוך `AppData` לתיקייה פרטית
   (`AppData\Local\Packages\Claude_…\LocalCache`). העותק הקודם
   (`%LOCALAPPDATA%\PIVO\worker-production`) נוצר מסשן Claude ולכן היה קיים
   **רק** בתוך Claude: קיצור ה-Startup הצביע על נתיב ש-Windows עצמה לא רואה,
   העובד מעולם לא עלה לבד בכניסה, ורץ רק כשסשן הפעיל אותו — ומת איתו.
   נתגלה 24.09.2026 כש-Task Scheduler החזיר «Can not find script file».

   **Watchdog (24.09.2026):** אותו סקריפט גם רושם משימה מתוזמנת
   (`PIVO Automation Worker Watchdog`, דרך `install-watchdog.ps1`) שמפעילה את
   `start-worker.vbs` כל 5 דקות — גם על סוללה, וגם כשהמחשב חוזר משינה.
   כשעובד כבר רץ, ההפעלה הנוספת יוצאת מיד ובשקט (`src/singleInstance.mjs`).
   ביטול: `Unregister-ScheduledTask -TaskName 'PIVO Automation Worker Watchdog' -Confirm:$false`.

   **הפעלה מחדש (למשל אחרי עדכון גרסה):** רק דרך
   `powershell -NoProfile -File worker\restart-worker.ps1` — לא `Start-Process`/`wscript`
   מתוך טרמינל של סשן Claude או IDE. עובד שהופעל כך הוא צאצא של אותה אפליקציה
   ונסגר איתה; כך בדיוק העובד הקבוע נפל ב-24.09.2026 בשינה של 07:24.

## הרצה

בשגרה — אין. העובד עולה לבד עם המחשב.

להרצה ידנית (פיתוח/אבחון):
```bash
cd worker
npm start
```

הרצה שקטה כמו בפרודקשן: `wscript worker\start-worker.vbs`
(הפלט נכתב ל-`worker\worker.log`).

או ישירות: `node worker/src/index.mjs`.

הפלט מדפיס כל תפיסת משימה, ההתקדמות שלה, והתוצאה. `Ctrl+C` עוצר בצורה
מסודרת — משימה שכבר בביצוע ממשיכה עד הסוף (או עד שהחכירה פוקעת, ואז נתפסת
מחדש בהרצה הבאה — ראה §"חוסן" למטה).

## מבנה

```
worker/
├── src/
│   ├── index.mjs        לולאת הרצה: heartbeat → claim → dispatch → report
│   ├── config.mjs        קורא worker/.env
│   ├── apiClient.mjs      עטיפת HTTP ל-edge function automation-worker
│   ├── dispatcher.mjs     מרשם ה-handlers — כאן אוטומציה חדשה נרשמת
│   ├── errors.mjs         NeedsHumanError / PermanentError
│   └── handlers/
│       └── devTestAutomation.mjs   הפעולה היחידה של אבן דרך 1
└── .env.example
```

## איך מוסיפים אוטומציה #2

1. ליצור `src/handlers/<שם>.mjs` שמייצא `actionType`, `preflight()` ו-`run(ctx, input)`.
   `run` מחזיר `{ result, facts?, artifacts? }`, או זורק `NeedsHumanError`/`PermanentError`
   (ראה `errors.mjs`) — כל שגיאה אחרת מטופלת כ-failed רגיל.
2. לרשום אותו ב-`dispatcher.mjs` (import + הוספה למערך `HANDLERS`).
3. זהו. הלולאה, החכירה, הדיווח וה-heartbeat כבר קיימים ומשותפים.

## ייצוג בשע״ם — שלוש הפעולות (194)

שלוש פעולות נפרדות, כי הן נפרדות בזמן ובאחריות:

| action_type | מה היא עושה | מתי |
|---|---|---|
| `shaam.create_representation` | אימות ישות ← בקשות ייפוי כוח ← פרטי התקשרות, ואז מביאה את טופס 2279 שנוצר לתיק הלקוח | לפני החתימה |
| `shaam.submit_poa` | מאתרת את הבקשה לפי מספרה, ומעלה את הטופס **החתום** | אחרי החתימה והחותמת |
| `shaam.check_representation` | קוראת «מצב בקשה» ו«מצב מערך» מרשימת הבקשות. **קוראת בלבד** | בכל שלב |

**מה מגיע מ-PIVO ומה לא.** רשימת המערכים לסימון מגיעה ב-`input.systems`
ונגזרת מ«חובת ייצוג מול» שעל הבקשה. העובד מסמן בדיוק אותה, ועוצר אם נשארה
מסומנת שורה שלא ביקשנו. פרט חסר בכרטיס (טלפון בן/בת זוג, ת.ז. הורה, מספר
תיק) עוצר **לפני** פנייה לרשות — ולעולם לא מושלם בניחוש.

**אימות ישות מנוסה פעם אחת.** דחייה של שע״ם ⇒ `needs_human`, בלי ניסיון שני.
ניסיונות חוזרים על אימות זהות עלולים לחסום את המשתמש בשע״ם.

**חלוניות.** מאושרות רק החלוניות שברשימה הסגורה ב-`SHAAM_KNOWN_DIALOGS`
(`shaamRepresentationSession.mjs`). כל חלונית אחרת עוצרת את הפעולה.

**«נשלח לשע״ם» אינו לחיצה.** הפעולה מחזירה `submitted: true` רק כשהמסך הציג
ראיה לקליטה; הטריגר בשרת (194) כותב את התאריך רק על הדגל הזה.

**מסמכים.** הטופס נכנס ויוצא דרך `put_document` / `get_document` ב-edge
function — בגבול ה-job שהעובד מחזיק, בלי מסלול «שמור לשולחן העבודה».

בדיקות (בלי Playwright, פונקציות טהורות): `npm run test:worker`.

## חוסן — למה זה בטוח להרוג את התהליך באמצע

כל משימה נתפסת עם **חכירה** (lease) שפוקעת אחרי זמן קצוב. אם התהליך נהרג,
המחשב נרדם, או הרשת נופלת — אף אחד לא "משחרר" את המשימה בכוונה, אבל ברגע
שהחכירה פוקעת היא הופכת שוב לזמינה לתפיסה (על ידי אותו עובד בהרצה הבאה, או
עובד אחר). שום משימה לא נתקעת לצמיתות. ראה `supabase/150-automation-jobs.sql`
ו-`scripts/verify-automation-jobs.mjs` (מוכיח את זה על סביבת הבדיקות).

## אבטחה

- העובד מחזיק **רק** את `PIVO_WORKER_SECRET` — לא מפתח service-role, לא סיסמה,
  לא טוקן גישה למסד. הסוד הזה מוגבל ל-4 פעולות בלבד (claim/heartbeat/complete/fail)
  דרך ה-edge function `automation-worker`.
- העובד לעולם לא שומר עוגיות, טוקני סשן, PIN, OTP, או פרטי אישור דיגיטלי —
  גם באוטומציות עתידיות שכן פותחות דפדפן. אימות מול רשות ממשלתית תמיד ביד אדם.
- `worker/.env` מקומי בלבד ואינו נכנס ל-Git.
